# Assumptions

Every assumption the project runs on, with the story that made it. Rows are added at the end; a wrong one is marked, never deleted (rule 26).

| Date | Story | Assumption | Why | Check that would prove it wrong |
|---|---|---|---|---|
| 10 Nov 2026 | #319 (A15) | A code file is any changed file that is not `.md` or `.txt` and not under `docs/` or `pm/`. A `.yml` workflow or a `.sh` script counts as code. | A TDD rule needs a line between "code" and "docs". CI workflows change behaviour, so they count as code. | A code change that lands under `docs/` or `pm/` with no test, or a doc-only PR that fails because of a `.yml` file. |
| 10 Nov 2026 | #319 (A15) | A PR into `main` (promotion) and a PR from `main` (back-merge) are exempt from the TDD check. | Rule 24: `main` holds run-critical code only and the changes there were already reviewed on `dev`. | A feature PR that targets `main` directly (it would be exempt by mistake). |
| 10 Nov 2026 | #319 (A15) | A test is named by its path (`tests/test_x.py`), with an optional `::test_name`. The path must equal a file in the PR diff. A file that only gets deleted is not evidence. | The check reads the body as text and the diff from git; it does not parse test function names. | A test named by a bare file name (`test_x.py`) that the check rejects, or a deleted file that passes. |
| 10 Nov 2026 | #319 (A15) | Before a push, `check_local.sh tdd` reads the commit log as the PR body, the same way the frontend-design and story checks do. CI reads the real PR body. | No PR body exists before a push. | A commit message that names a test and passes locally but fails in CI (the body differs). |
| 10 Nov 2026 | #325 (A7) | A workflow's `on:` block is read by indent: a trigger key sits two or more spaces under `on:`, or the value is inline (`on: [workflow_run]`). A flow-style `on:` map with nested braces is not parsed. | The check reads text, not a YAML tree, to stay stdlib only. | A workflow with a nested-brace `on:` map and a risky trigger that the check passes. |
| 10 Nov 2026 | #325 (A7) | A checkout step is one list item (the dash column bounds it). A `ref:` or `repository:` line inside that item, with a PR-head expression, is the PR head checkout. | A step is the unit that holds both the checkout and its `ref:`. | A PR-head checkout whose `ref:` sits outside the list item, passed by the check. |
| 10 Nov 2026 | #325 (A7) | A shell command is one logical line: a trailing backslash joins the next line, and `--ignore-scripts` must sit on that same command. An `npm ci` split by any other construct is not seen. | Backslash joins are the one split that real workflows use. | An `npm ci` written across a heredoc or `&&` chain that installs scripts and passes. |
| 10 Nov 2026 | #325 (A7) | `npm i` counts as an install (it is an alias of `npm install`). `npm` flags placed before the subcommand (`npm --prefix x ci`) are not seen. | `npm i` is common; flags before the subcommand are rare here. | A workflow using `npm --prefix x ci` without `--ignore-scripts` that the check misses. |
| 10 Nov 2026 | #325 (A7) | `run:` values that only name npm in a `name:` or a comment are not commands, so they are not checked. | Only a `run:` line executes; a name or comment does not. | A false alarm on a `name:` line, or a miss on a real command written in a comment-like line. |
| 10 Nov 2026 | #325 (A7) | `vendor-backup.yml` has no real `npm ci` run line: its `npm ci --offline` text sits in a `name:` line and the install runs inside `restore_vendor.sh`. So the repo's own workflows pass without an exception. | Read from the file on 10 Nov 2026. | The repo's own workflows fail the check, or `vendor-backup.yml` gains a real `npm ci` line. |
