# Demo note: v0.8.0 (5 Nov 2026)

What to show, in order.

1. Open `.shipquick/roles.yml`. It names who may code and who may review this project, and
   `scripts/review_merge.sh` reads it to refuse a PR authored by anyone else.
2. Open `scripts/protected_paths.txt`. A PR that touches one of these (CI config, `review_merge.sh`
   itself, the roles file) is refused in Auto mode — "protected path, owner merges" — even with a green
   gate and an approval.
3. Open `scripts/freeze.sh` and run `bash scripts/freeze.sh status`. With nothing frozen it prints "not
   frozen"; it reads `origin/main`, not a local file that could be stale.
4. Open `docs/templates/feedback.md` and `scripts/feedback.sh --help`-shape usage in its header comment. A
   child project raises a gap here with one command, not a PR.
5. Open `docs/MODES.md`'s per-role table. Auto mode needs a coder account and a different reviewer account
   — one account playing both roles can never set Auto (`scripts/mode.sh set auto` refuses it).
