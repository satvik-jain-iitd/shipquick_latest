# ADR-017: Gate files live on every code branch of a kit-branch child

Date: 2026-11-12
Status: Accepted (story #479, feedback #478). Changes the rule-24 flow of story #225.

## Context

A rule-24 child keeps the kit on its own branch (the kit branch). Story #225 let `main` carry only the caller, and
CI read the pin, the hook config and the roles from the kit branch. But git hooks run on the checked-out branch and
read `.pre-commit-config.yaml` from it. On a code branch every commit stopped with "No .pre-commit-config.yaml file
was found". An agent got past it with `PRE_COMMIT_ALLOW_NO_CONFIG=1` on six child PRs, which skips every hook.
`adopt.sh --check` passed all the while, because it read the hook config from the kit branch. The owner paused the
child until this is fixed.

## Decision

- A short list of gate files, "group A", lives on every code branch, equal to the kit branch copy. Documents stay
  on the kit branch. This is a layout, not a resolver: nothing new reads another branch.
- One list, `scripts/gate_files.txt`, a protected path. It was derived by reading the hook entries `adopt.sh` writes
  and the files `check_local.sh` and `session_trailer.sh` read, not guessed: the hook config, `.gitmodules` and the
  submodule pin, both callers, `roadmap.json` (the roadmap workflow reads it from its checkout),
  `.shipquick/features.json` (a missing file means every default) and `.shipquick/roles.yml`.
- `CLAUDE.md` is not a gate file. The hook's `rule-copies` check reads only the kit's own copy.
- `adopt.sh --gate-files` copies the list from the kit branch and stages it. It writes no document and never commits.
- `adopt.sh --check` on a code branch fails for each gate file that is missing, differs from the kit branch, or is
  only on the code branch. One rule for every file, the pin included. It compares the file on disk (what the hooks
  read), the index for the pin, and only the kit entry of `.gitmodules`. The kit branch is read from origin first.
- A branch cut from the kit branch and nearer to it than to `dev` (the rule of story #469) is kit-branch work, a bump
  for example. It is read at HEAD and not compared, or the check would tell a bump to undo itself.
- A missing or empty list is exit 2 in both modes, never "nothing to check".
- The first hook, `shipquick-kit`, turns "kit folder not checked out" into one line that names the fix.
- `plugin/hooks/git_guard.py` refuses the two no-config switches (story #480).

## Options not taken

- A resolver that makes the hooks read the config from the kit branch (the first idea in feedback #478): one more
  reader of another branch, and it needs every clone to have fetched that branch.
- `pre-commit --config` pointing at a file outside the branch: the same problem, and it hides the config from review.

## Radar

Two `scout.py` runs and a GitHub topic search on 12 Nov 2026 found no repo for "keep the hook config on every
branch" (`docs/research/repo-radar.md`). The `pre-commit` framework itself is reused as it is.

## Consequences

- A kit bump in a kit-branch child is two steps: bump on the kit branch, then `--gate-files` on each code branch.
  `--check` fails with the fix until both are done.
- A child that kept only the caller on a code branch reads "not adopted" from `--check` until it runs `--gate-files`.
  CI's `adoption` job is unchanged: it still reads the pin and the hook config from the kit branch.
- Not done here: CI does not yet fail a code branch whose gate files differ from the kit branch (`docs/follow-ups.md`).
