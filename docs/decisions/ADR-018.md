# ADR-018: One change map decides which slow CI jobs run, and the gate proves it

Date: 2026-11-13
Status: Accepted (story #485, PR 1 of 4)

## Context

The phone jobs (`ui-android-*`, `ui-ios-*`) need macOS for the iOS side, and that machine is scarce. Story #484 took
`ci.yml` out of the path rule, but the rule itself was still two `grep` lines inside `ci.yml`. The local check could not
read it, a child could not reuse it, and the gate did not prove that a needed job had run.

## Decision

1. One map, `scripts/change_map.json`, names the areas (`android`, `ios`), the jobs of each area, and the paths that turn
   the area on. `free` lists the paths that need no slow job. JSON, because the standard library reads no YAML (#464).
2. One reader, `scripts/change_map.py`, stdlib only. `decide` prints `{android, ios, all, reasons}`. `gate` checks the
   results of the gate's `needs`: a job of an on area must be `success`; a job of an off area may be `skipped` or
   `success`; a missing result is wrong.
3. Fail closed. Every area is on when: the event is not a pull request; the diff cannot be read; the map is missing,
   empty or broken; the map or the reader changed in the PR; a changed path no row names (the reason names the path and
   the row to add). Any crash inside the reader is the same as a doubt.
4. A change to one phone job's own steps in `ci.yml` turns that job's area on. The block of a job is the text from its
   key to the next job key; a change anywhere else in `ci.yml` turns nothing on.
5. The reader and the map are read from the base branch in `ui-changes`, so a PR cannot weaken the rule it is judged by.
   The gate runs the reader from its own checkout (the commit under test). Both files are protected paths: the owner
   merges a PR that touches them.
6. Renamed files count under the old path and under the new one (`git diff --no-renames`).

## Changes in meaning, each with its reason

- **Every path that turned a job on before still does** (a table test in `tests/test_change_map.py`): `ui/`,
  `tests/fixtures/`, `scripts/ui_proof.py`, `scripts/emit_contracts.py`, `scripts/emit_tokens.py`, `design/` turn the
  compile and lint jobs on; `ui/ios/`, `design/`, `scripts/emit_tokens.py` turn the snapshot job on. Nothing was dropped
  from those lists.
- **`ui/android/**` no longer turns the iOS jobs on.** This is the goal of the story: an Android-only PR does not wait for
  a macOS machine. Reason: the iOS jobs read only `ui/ios/`, `ui/tool/ios_*`, `tests/fixtures/ios/`, `design/`,
  `scripts/emit_tokens.py` and the shared paths (checked by a grep of each job's text, see the PR body).
- **`ci.yml` is not a path** (story #484 already): its job steps are covered by rule 4 instead.
- **Paths that were free stay free**: `docs/`, `pm/`, `plugin/`, `roadmap/`, `tests/` (outside the fixtures), `scripts/`
  (outside the list above), `.github/` (outside the job blocks), `knowledge/` (the kit submodule), and the root files
  `*.md`, `.gitignore`, `.gitattributes`, `.pre-commit-config.yaml`, `roadmap.json`, `CLAUDE.md`.

## Known limits, written down

- A phone job reads only the paths listed in its area today. A later job that reads a new path (a `scripts/` file, a
  `.github/` action) must add that path to its area, or the gate cannot see it. The reviewer checks this in the PR; a
  test of the job text is a follow-up.
- A change to a top-level `env:` or `defaults:` block of `ci.yml` (none today) is outside every job block and turns
  nothing on. A PR that adds one must name the jobs it affects.
- The gate's result check trusts GitHub's `needs` context, and the reader in the gate's checkout is the PR's copy.

## Radar

On 13 Nov 2026 `scout.py` (need: "decide which CI jobs must run from the changed paths of a pull request, fail closed,
one map file read by CI and local checks") printed `no repos found`. GitHub topic search found `dorny/paths-filter` (MIT,
pushed 27 Sep 2026) and `step-security/paths-filter` (MIT, a fork, pushed 9 Nov 2026). Both run only inside a workflow, so
`check_local.sh` and a child's caller could not read the same map, and both add a third-party action to a protected
workflow. Borrowed: the filter file and the base rule per event. Not borrowed: the action. Recorded in
`docs/research/repo-radar.md`.

## Consequences

- A child that wants the same rule gets the map and the reader with `adopt.sh` (PR 4). Its areas are its own.
- The nightly full run (PR 3) is the net for anything the map cannot see.
