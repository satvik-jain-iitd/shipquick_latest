# ADR-011: Maker and checker are different sessions, not only different accounts

Date: 2026-11-09
Status: Accepted (reviewer approved 9 Nov 2026, issues #139 and #149)

## Context

ADR-010 and story #140 made the gate check accounts. The PR author must be a coder account.
A different reviewer account must approve. That still has one hole.

Two agent sessions often run on one machine. Both can see both `gh` logins.
So a reviewer session can borrow the build account, write the commits, open the PR,
and then approve as the review account. Every account rule passes. One pair of eyes saw the work.
This happened in a child project on 30 Oct and 3 Nov 2026 (the worked example in #139 and #149).

The owner's rule: the one who builds a thing never verifies it. The same holds for agent sessions.

GitHub only sees accounts. So the session has to be written down where a script can read it.

## Options

- **(a) A session trailer on every commit, and a session line in the approving review.**
  Each commit carries `Built-by: <session>`. The approving review carries `Reviewed-by: <session>`.
  `roles.yml` lists which sessions are coders and which are reviewers.
  The `roles` CI job and `review_merge.sh` compare them.
- **(b) One token per session.** Each session sees only its own `gh` login.
  Strong, but it lives in the machine setup (keychains, env), not in the repo.
  A kit script cannot prove it from CI. It also breaks the case of one human with one account.
- **(c) Signed commits per session.** Strong, but needs keys per session and a rotation story.
  Too heavy for every child.

## Decision

**Option (a).** Option (b) stays a recommended setup step in `docs/MODES.md`, not a gate.

1. `roles.yml` gains two optional lists: `coder_sessions:` and `reviewer_sessions:`.
   Example: `coder_sessions: [shipquick-dev]`, `reviewer_sessions: [shipquick-qa]`.
   The names come from `docs/TEAM_ROSTER.md` (rule 27: `<project>-dev`, `<project>-qa`).
2. Every non-merge commit on a PR carries a `Built-by: <session>` trailer.
   A `prepare-commit-msg` hook (installed by `adopt.sh`) adds it from `$SHIPQUICK_SESSION`.
   `role.sh` sets `$SHIPQUICK_SESSION` when a session takes its role.
   No env var and no trailer: the hook writes nothing, and CI fails the commit with the fix.
3. The `roles` CI job: when `coder_sessions` is set, every non-merge commit must name a coder session.
   The same merge-commit exemption as ADR-010 applies.
4. The approving review body carries `Reviewed-by: <session>`. The review is already a teammate block,
   so its header `from <session>` is accepted as the same line. `review_merge.sh` refuses when:
   the approver names no session, names a session not in `reviewer_sessions`,
   or names a session that also appears in any `Built-by:` trailer of the PR.
5. Opt-in by data, not by flag: with no `coder_sessions` in `roles.yml`, every session check is skipped
   with one printed line. A child turns it on by adding the two lists in a PR the owner merges
   (`roles.yml` is a protected path). No child breaks on the pin bump.

## What this does not stop

A trailer is self-declared. A session that types another session's name on purpose passes.
This closes the accident the issues show: a reviewer that builds because the owner asked it to,
and then approves its own work without noticing. It does not close deliberate forgery.
Option (b), one token per session, is the next layer against that. It is named in `docs/MODES.md`.

## Consequences

- Every coder commit gets one more trailer line. The hook writes it, so nobody types it.
- A reviewer that has to fix something itself must hand the review to the other session (rule 30).
  The gate now says so, instead of the harness refusing by luck.
- `check_roles.py` and `review_merge.sh` each grow a small session check. `roles.py` learns two keys.
- The kit itself adds `coder_sessions: [shipquick-dev]` and `reviewer_sessions: [shipquick-qa]` in a
  follow-up PR, after the open PRs land, so no open PR goes red on commits made before the hook.
- Reviewer refinement (9 Nov 2026): one session name may never appear twice in `roles.yml`.
  `roles.py` refuses such a file, so every script that reads it refuses too.
- Existing children keep their own `.pre-commit-config.yaml`; `adopt.sh` adds the hook only to a new one.
  `docs/MODES.md` names the one-line install.
