# ADR-003: Close linked issues by hand after a merge into dev

Date: 2026-10-14
Status: Accepted

## Context

Every PR body says `Closes #N`. We thought GitHub closes the issue on merge.
It does not. GitHub auto-closes only when the PR merges into the default branch (`main`).
Our feature PRs merge into `dev`. So the issues stayed open.
In GoServe, 15 story issues (#39 to #54) were still open after their PRs were merged.

## Decision

- Keep `Closes #N` in the PR body. It works for PRs into `main`.
- When the base is not the default branch, the PR checklist adds one item:
  "Close issue #N by hand after merge, with a comment linking this PR."
- After the owner says the PR is merged, run `python3 scripts/close_linked_issues.py <pr>`.
  It reads `gh pr view <pr> --json state,baseRefName`.
  If the state is MERGED and the base is not the default branch, it lists the linked open story issues.
  The owner gives one yes. Then `--yes` closes each with `Done in PR #X (squash-merged to <base>).`
- It never closes epics (label `epic`). It closes only story issues linked by `Closes #N`.
- It never closes an issue whose PR is open, or closed without a merge.
- The dry run is the default. Nothing closes until `--yes`.

## Consequences

Good:

- Issues match reality. The board shows Done when the work is done.
- One command, one yes, all linked issues closed with a trace back to the PR.
- The script is tested with a fake `gh`, so the rules cannot drift by accident.

Bad and to watch:

- One more step after each merge into `dev`. The checklist item is the reminder.
- Issues linked only in commit messages, not in the PR body, are not seen.

## Rollback

- Delete `scripts/close_linked_issues.py` and its test. Remove the checklist item.
