# ADR-020: Role-based model profiles and an XS-or-S story size gate

Date: 2026-11-19
Status: Accepted (owner request, 19 Nov 2026)

## Context

ShipQuick runs two agent sessions: `shipquick-dev` (coder) and `shipquick-qa` (reviewer and orchestrator). Both use the same free-tier pool, and the kit now asks stories to stay XS or S. Two gaps:

1. The sessions used one model for both roles. Review work (full diff + design + architecture direction) needs a large context window and reasoning; coding work needs speed. One model cannot be best at both.
2. The T-shirt size in `pm/agile/REFINEMENT.md` was advice, not a gate. M, L and XL stories still entered Ready, and a fast coder model then tried to carry them.

## Decision

1. Role model profiles. QA uses a reasoning model with a large context window (default `opencode/beam-free`, 1.05M context, reasoning on); dev uses a fast model (default `opencode/deepseek-v4.1-flash-free`, 200k context). Both are free-tier (cost 0, VERIFIED from the model registry). Each profile carries a fallback order. The pin lives in the project's `opencode.json` under the `agent` block, not in the repo's committed config.
2. Story size gate. Only `XS` and `S` may be planned. A story with size `M`, `L` or `XL` must be split before it leaves Ready. `scripts/check_story_size.py` fails when a `user-story` issue (created on or after 2026-11-19) has no size or a size outside `{XS, S}`. The check runs in CI on PR bodies and locally through `scripts/check_local.sh`.
3. The issue template gains a `Size` dropdown (XS, S, M, L, XL) and a DoR checkbox: "Size is XS or S (M, L, XL must be split first)".
4. `pm/agile/REFINEMENT.md` states the rule in the T-shirt size section and in the Definition of Ready.

## Consequences

- A model choice is now a kit decision, not a chat decision. Changing it needs a new ADR.
- No story enters Ready above S. Large work becomes several PRs by construction.
- The free-tier day cap is shared across projects, so each lane keeps its fallback order.
- The check is skipped for stories created before 2026-11-19, the same grace the `Who does it` check uses.

## What this does not stop

The model pin is per machine, not per repo. A child project can pick any free model; the kit only requires the split and the size gate. A reviewer that types a size in the body can still ship a large story: the check reads the issue, not the code.
