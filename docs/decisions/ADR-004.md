# ADR-004: One teammate-block protocol for any team, checked by code

Date: 2026-10-15
Status: Accepted

## Context

ADR-003's follow-up, the v1 team protocol (#35), fixed three roles (owner, coder, reviewer) and
assumed GitHub PRs. Two older protocols on the owner's Mac said different things: one used a fenced
block in English to the coder and Romanized Hindi to the owner; the other used `@Role` paragraphs
and a `STATE.md` file that no project ever had. Roles were hardcoded in each. Nothing checked a
block's shape, so a sloppy block cost the owner a re-read and a re-paste.

## Decision

- One grammar for every team: `To <role>, from <role>, re <ref>:`, numbered imperatives, under 120
  words, last line `Need from you: ...` or `Nothing needed from you.`
- `<ref>` is any stable handle, not only a PR. `<role>` comes from `docs/TEAM_ROSTER.md`.
- English always inside the block. Owner lines in Romanized Hindi stay in chat above the block.
  Reason: one language lets a regex check the block, and it ends the contradiction between the
  two older protocols.
- The owner is the only relay (hub). No direct agent-to-agent messaging. Reason: the owner wants to
  see and approve every handoff. Blocks are also stored on GitHub where a PR exists, so the owner
  can relay by link.
- `scripts/check_block.py` checks the shape with regex only (micro-tasking rule: code before any
  model). CI job `team-block` runs it on the `## For the reviewer` section of every PR body.
- The canonical text is the global skill `~/.claude/skills/team-protocol/SKILL.md`. ShipQuick ships
  a copy. The two older protocols become pointers to the skill.

## Consequences

Good:

- Any project, any tool, any number of roles: copy the roster, keep the grammar.
- A bad block fails in CI before the owner sees it.
- One source of truth. Three contradicting copies become one.

Bad and to watch:

- Every PR, docs-only too, needs a real block or `team-block` fails. On purpose.
- Two copies (skill and ShipQuick doc) can drift. The skill wins. Sync by full copy only.
- A child project gets the CI check only after a submodule bump and a copied `ci.yml` job.
- The check does not know the roster, so a misspelt role name passes. Add that check if it bites.

## Rollback

- Delete `scripts/check_block.py`, its test, and the `team-block` job. Keep the docs.
