# ADR-021: Intent-verification gate between QA and Dev

Date: 2026-11-19
Status: Accepted (owner request, 19 Nov 2026)

## Context

ShipQuick runs two agent sessions: `shipquick-dev` (coder, fast model) and `shipquick-qa` (reviewer and orchestrator, reasoning model). QA is on a larger reasoning model; Dev is on a faster implementation model. A fast model can misread a QA delegation and start coding the wrong thing. The cost of a misunderstanding is a wasted PR and a re-review cycle.

## Decision

1. Before Dev starts any work delegated by QA, Dev sends a say-back message: what it understood, its planned approach, and an explicit question ("am I doing this right?"). Dev does not code until QA replies "confirmed" (or corrects).
2. The confirmation is recorded in the PR body as `Intent verified by QA: <YYYY-MM-DD>`.
3. `scripts/check_intent_verify.py` fails a dev-authored PR (linked to a user-story issue created on or after 2026-11-19) that lacks the `Intent verified by QA:` line.
4. The check runs in CI on PR bodies and locally through `scripts/check_local.sh`.

## Consequences

- A misunderstanding is caught before code is written, not after review.
- The gate is auditable: the PR body carries the confirmation date.
- Dev on a smaller model is still safe because it must confirm intent first.

## What this does not stop

QA types the confirmation as a comment on the story issue, from its own login. The gate checks that the comment has the phrase and a date, and that its login is not the PR author. It does not check the say-back itself.

Still open: a QA that confirms without reading the say-back passes, because the gate does not read the say-back. A coder that edits the issue body does not pass, because only comments count. A coder that writes a comment from a second login passes if that login is not the PR author; the gate names no account, so the kit cannot tell a QA login from any other.
