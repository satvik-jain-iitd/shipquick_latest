# ADR-021: Intent-verification gate between QA and Dev

Date: 2026-11-19
Status: Accepted (owner request, 19 Nov 2026)

## Context

ShipQuick runs two agent sessions: `shipquick-dev` (coder, fast model) and `shipquick-qa` (reviewer and orchestrator, reasoning model). QA is on a larger reasoning model; Dev is on a faster implementation model. A fast model can misread a QA delegation and start coding the wrong thing. The cost of a misunderstanding is a wasted PR and a re-review cycle.

## Decision

1. Before Dev starts any work delegated by QA, Dev sends a say-back message: what it understood, its planned approach, and an explicit question ("am I doing this right?"). Dev does not code until QA replies "confirmed" (or corrects).
2. QA records the confirmation as a comment on the story issue: `Intent verified by QA: <YYYY-MM-DD>`, from a login on the reviewer list (`scripts/roles.py get reviewer`) that is not the PR author. The PR body does not count.
3. `scripts/check_intent_verify.py` fails a PR (linked to a user-story issue created on or after 2026-11-19) whose story issue has no such comment.
4. The check runs in CI and locally through `scripts/check_local.sh`. Both judge the same comments.

## Consequences

- A misunderstanding is caught before code is written, not after review.
- The gate is auditable: the story issue carries the confirmation comment and its date.
- Dev on a smaller model is still safe because it must confirm intent first.

## What this does not stop

QA types the confirmation as a comment on the story issue, from a login on the reviewer list. The gate checks that the comment has the phrase at the start of its line, a date, and that its login is on the reviewer list and is not the PR author. It does not check the say-back itself.

Still open:

- A QA that confirms without reading the say-back passes, because the gate does not read the say-back.
- A login with write access can edit another login's comment after QA posts it; the gate reads the comment as it is when checked.
- A coder that edits the issue body does not pass, because only comments count.
- A link to an old or unlabelled issue skips the gate, and the date is not checked against anything.

The check runs in the kit's CI and in a child's CI (job `intent-verify` in checks.yml, feature `intent-verify`, on by default; story #576). The local check runs in a child too, from the child's own copy of the kit.
