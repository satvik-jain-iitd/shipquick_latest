# ADR-022: Graphify as the structural knowledge source

Date: 2026-11-19
Status: Accepted (owner request, 19 Nov 2026)

## Context

ShipQuick has no dependency graph. `plugin/hooks/map.py` is a regex-based name/folder summary with a 2000-character budget and is not a parser. The audit (docs/research/gap-audit-2026-11-19.md) identified this as a core gap: test selection, architecture queries, and change-impact analysis all need structural evidence.

## Decision

1. Use the open-source Graphify CLI (`graphifyy` package, command `graphify`) as the structural knowledge source. Code extraction is AST-based via tree-sitter and is deterministic; no LLM and no API key is needed when running with `--code-only`.
2. Pin the exact version in `scripts/graphify_version.txt` (currently 0.9.112). A freshness check (`scripts/check_graph_fresh.py`) fails when the installed version differs.
3. Run `graphify extract <path> --code-only --no-cluster --no-viz` to produce `graphify-out/graph.json`. Use `graphify affected` for reverse-dependency impact.
4. Do not commit `graphify-out/` by default. Generate in CI and publish as an artifact; local developers generate on demand. Revisit if size/churn justify committing.
5. Graphify supplies source-to-source structural evidence only. ShipQuick's own test-impact manifest (M2) is authoritative for test selection. Graph edges alone are not proof that a test can be skipped.
6. No paid service or hosted endpoint is required for core correctness.

## Consequences

- Deterministic code graph with no LLM dependency for code-only extraction.
- Freshness is verified by source SHA, schema version, and CLI version.
- `affected` gives reverse dependents for change-impact analysis.
- Docs/images are not extracted in code-only mode; that is acceptable for test selection.

## What this does not stop

Graphify cannot prove all runtime dependencies (dynamic dispatch, reflection, DI, generated code). The selector must fail closed on uncertainty.
