# ADR-023: Versioned test-impact manifest and conservative selector

Date: 2026-11-19
Status: Accepted (owner request, 19 Nov 2026)

## Context

ShipQuick has no general source-to-test selection. CI runs the full Python suite and Node roadmap tests on every PR. The audit (docs/research/gap-audit-2026-11-19.md, G01) identified this as the central gap. Graphify (ADR-022) supplies structural evidence, but graph edges alone are not proof that a test can be skipped.

## Decision

1. A versioned, schema-validated manifest at `.shipquick/test-impact.yml` controls test selection. It describes languages/packages, source globs, test globs, runners, commands, explicit source->test mappings, global-impact paths, contract groups, and full-suite commands.
2. A conservative selector reads the manifest + graph and computes the smallest safe test set. Unknown/ambiguous/stale/unclassified inputs force full-suite fallback. The selector never produces an empty set for a non-docs source change.
3. Manifest invalidity (unknown keys, bad globs, duplicate IDs, missing commands, invalid test paths) fails the selector check.
4. A dry-run mode prints the planned mapping without running tests.
5. A child is eligible for selective execution only after manifest + graph pass completeness validation. Unmapped children run the full suite.
6. Graphify is an input, not an oracle. Explicit manifest mappings are authoritative; Graphify contributes source-to-source dependency evidence.

## Consequences

- Test selection is deterministic for the same base/head SHA, manifest, graph, and tool versions.
- Uncertainty always expands coverage.
- Children adopt incrementally (unmapped => full suite).

## What this does not stop

The manifest cannot prove all runtime dependencies. Dynamic dispatch, reflection, DI, generated code, and environment-driven wiring require explicit global-impact paths or full-suite fallback.
