# ADR-002: PR merge gates enforced by the machine

Date: 2026-10-11
Status: Accepted

## Context

Branch protection was on for `dev` and `main`. But the required status checks list was empty.
So a red CI did not block the Merge button. The merge decision was left to a person.

## Decision

Make the machine decide when a PR can merge. Set these gates:

- One required status check on both `dev` and `main`: `gate`. It passes only when every CI job passes. This avoids the matrix job naming trap, where a skipped `test (3.12)` is reported as `test`.
- Required branch up to date.
- Required conversation resolution.
- One approval, approver is not the author.
- Auto-merge off. The owner reviews, comments, approves, then merges every PR by hand.
- Delete branch on merge.

Merge formula:

```
merge = CI AND approval AND no-open-comments AND up-to-date AND not-draft AND linked-issue
```

## Consequences

Good:

- Broken code cannot reach `dev` or `main`.
- The rule is the same for every PR.
- Fewer stale branches.
- The repo shows structured, fast development for anyone who clones it.

Bad and to watch:

- Small docs fixes also need a branch, a PR, and an approval.
- A renamed CI job can lock merges. Update protection when a job name changes.
- Skipped required checks must be tested once before trusting them.
- Admin is not exempt, so an emergency needs a short protection-off window.

## Rollback

- Remove rule: `DELETE .../branches/{branch}/protection`.
- Turn auto-merge off in repo settings.
