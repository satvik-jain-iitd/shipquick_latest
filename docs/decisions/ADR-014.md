# ADR-014: A kit rule wording change must beat the current kit on the bench

Date: 2026-11-10
Status: Accepted (story #312, A1b of epic #309)

## Context

ShipQuick has 38 rules on paper. Nobody has measured whether a rule helps. A rule can sound
right and still make a helper session worse: slower, dearer, or less correct.
The bench (`bench/run.py`) now runs the same ten tasks with and without the kit rules
(story #311 and #331). `bench/report.py` turns a run into one table.

## Decision

A change to the wording of a kit rule (any rule in CLAUDE.md that a session must follow) must
beat the current kit in a paired run on this bench before it merges.

- Paired run: the same tasks, the same models, the same number of runs, the current CLAUDE.md as
  one arm and the changed CLAUDE.md as the other arm.
- "Beat" means: the hidden-check pass rate is not lower, and the geometric-mean ratio of output
  tokens or cost is below 1.00 with its 95% interval not crossing 1.00, or the pass rate is higher.
  A tie is not a win. A tie is allowed for a pure typo fix.
- The table goes in `docs/research/experiments.md` in the same PR. A row is never deleted; a wrong
  row is marked superseded.
- A rule that only adds or removes a whole rule, or only fixes a typo, is not a wording change.
  The reviewer says so in the review.

## Consequences

- A paired run costs money (a live `claude` call per cell). The owner says yes first, every time.
- The numbers move with the model. A result is valid for the models in its row.
- Until the first live run exists, the row in `docs/research/experiments.md` says `pending`.
