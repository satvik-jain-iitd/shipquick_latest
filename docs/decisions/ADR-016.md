# ADR-016: Features are flags in one file, read by one reader

Date: 2026-11-11
Status: Accepted (story #418, F1 of epic #86)

## Context

ShipQuick grew many checks, jobs and scripts. A project cannot turn one off without editing the kit, and an agent
could switch off a check by editing a workflow. The owner asked (11 Nov 2026) for "everything is a plugin": each
feature on or off, per project, by the owner only.

## Decision

- One file per project, `.shipquick/features.json`, one row per feature id with `on`. It is a protected path, so
  only a PR the owner merges changes it.
- The kit lists every known id in `scripts/features_default.json`: its default, whether it is locked, and four plain
  words (`name`, `what`, `if_off`, `group`) that the Desk page shows. No text is hard-coded in a page.
- One reader, `scripts/features.py`, stdlib only. A missing file means every default. An unknown id is an error, never
  "on". A broken file is an error with its line, never a fallback. `adoption` and `gate` are locked: they read on
  whatever the file says, because they guard all the others.
- Off always means "the owner does more", never "a check is silently skipped" (CI job wiring is stories F4 to F8).
- `scripts/features*` joins `scripts/protected_paths.txt`.

## Borrowed ideas

From deepseek-ai/deepseek-harness (MIT, read as data on 11 Nov 2026, no code copied, no code run): one config row per
plugin keyed by a stable id; defaults in the kit and only departures recorded in the project; a read-only list with a
separate privileged way to change it; protected management pieces; broken entries shown, never hidden.
Not borrowed: in-process loading, hot reload, registry installs, layered patch files. ShipQuick features are CI jobs and
shell scripts, so "unload" is a job that skips.

## Consequences

Later stories read the same flags: `features.sh` (F2), `adopt.sh` (F3), CI jobs (F4 to F6), scripts (F7, F8), the Desk.
The kit's own repo has no `.shipquick/features.json` yet, so it runs every feature at its default.
