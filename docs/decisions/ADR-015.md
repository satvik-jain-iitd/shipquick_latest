# ADR-015: Rules reach every session and subagent through a plugin hook

Date: 2026-11-10
Status: Accepted (story #313, A2 of epic #309)

## Context

ShipQuick's rules live in CLAUDE.md. A Claude Code session reads that file, but a subagent does
not get the same context, and the mode is only checked when a session starts by hand. A helper
session can therefore run without the rules it must follow. Claude Code also drops SessionStart
context for subagents (Ponytail issue #252).

The story number for this ADR was planned as ADR-013, but ADR-013 already belongs to story #180.
This record takes the next free number.

## Decision

A plugin in `plugin/` runs two hooks, written in stdlib Python:

- SessionStart prints the mode (`.shipquick/mode`, or `not set`) and the ten load-bearing rules.
- SubagentStart returns the same text in `hookSpecificOutput.additionalContext`.

The rules come from `plugin/rules-dense.md`. `plugin/gen_rules_dense.py` writes that file from
CLAUDE.md, and a test fails when the committed file is stale. Every hook exits 0 on any error,
so it never blocks a session.

## Consequences

- A rule edit in CLAUDE.md turns the drift test red until the dense file is regenerated.
- The plugin only adds context. It does not enforce anything yet; the enforcement hooks come in
  A5a to A5c and A12.
- The map (A9) and the cost and loop guard (A12) are separate stories in the same lane.
- Not checked here: a live subagent transcript showing the rules. That needs the plugin installed
  in Claude Code, and the reviewer checks it there.
