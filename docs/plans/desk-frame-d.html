What is ShipQuick?

A helper kit for your project. It checks each change before it goes live. It keeps people and agents (AI helpers) in step.

What is this page?

Your Desk. It runs only on your computer. It shows what ShipQuick does in your project, and what waits for you.

What can I do here?

Pick a group on the left. Read what each feature does. Flip its switch to turn it on or off. A lock means it must stay on.

Overview

Feature groups

Protects your main branch

The main branch is the copy of your code that goes live. These features stop a bad change from getting in.

Final check

gate

Waits for every other check and gives one clear pass or fail for each change. Cannot be turned off: without it, a change could skip every check.

Always on

Kit link check

adoption

Makes sure your project uses a real, approved copy of ShipQuick. Cannot be turned off: it guards the switches on this page.

Always on

Agents may merge

merge-gate

An agent may accept (merge) a change once every check passes. If off: agents never merge. You accept every change by hand.

On

Try it before release

uat-on-main

Before a release, you tick a short test list on the test site (dev link). If off: a release can go live before anyone tries it.

On

Turn off "Try it before release"? Releases will go live without your test list.

We save this to .shipquick/features.json (your project's settings file). That file is protected, so it starts working only after you merge the PR we open.

Pause button

freeze

Changed from default

Lets you pause all changes to main, for example before a launch. If off: there is no pause; changes keep flowing.

Off

No hidden off-switches

disable-comments

Blocks code that quietly silences a check, unless a written decision says why. If off: a change can mute a check and no one sees.

On

Builder is not reviewer

roles

Checks that changes come from the builder account, so a different account reviews them. If off: one account could write and approve its own work.

On

Switch changes go to the settings file and start after your merge. Nothing changes the moment you tap.

Frame D, with the Overview group (story #437). Design rule shown: one pattern for everything (a panel is a panel). Why: Waiting, Decided, Roadmap and Spend open in the same right panel as a feature group, so the owner learns the page once.
