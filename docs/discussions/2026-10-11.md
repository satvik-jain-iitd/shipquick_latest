## PR and merge thinking

- Owner asked what a PR is and how to view it.
- Agent explained: a PR is a reviewable change, not a deployment.
- Owner asked if a PR can be treated like a sprint deployment.
- Agent explained three layers: unit PR (feat -> dev), increment PR (dev -> main), release (tag `D*`).
- Owner asked if a PR can be treated like a milestone.
- Agent explained: a milestone is a goal bucket, a PR is a member of it. A PR is not a milestone.
- Owner asked for a clear rule on when to merge.
- Agent gave the merge formula and the gate idea.

## Decisions

- Add machine-enforced merge gates. See ADR-002.
- One required CI check: `gate`. It passes only when every job passes.
- Auto-merge off. The owner reviews, comments, approves, then merges by hand.
- Delete branch on merge: on.
- Every PR links its issue with `Closes #N`.
