## Issue closing after a merge into dev

- Owner reported: `Closes #N` does not close the issue when the PR merges into `dev`. GitHub only auto-closes on a merge into the default branch. In GoServe, 15 story issues (#39 to #54) stayed open after their PRs were merged.
- Owner set the new rule: keep `Closes #N`; add a checklist item to close by hand when the base is not the default branch; after merge, check `gh pr view <n> --json state,baseRefName`, list the linked open issues, ask for one yes, close each with "Done in PR #X (squash-merged to <base>)."; never close epics; never close for an open or unmerged PR; show a dry-run list before closing anything.
- Agent built `scripts/close_linked_issues.py` with a test, and wrote the rule into `docs/PR_RULES.md`, the PR template, `CLAUDE.md`, and ADR-003.
