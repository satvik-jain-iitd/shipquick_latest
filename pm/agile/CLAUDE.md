# shipquick_latest — pm/agile/ Rules

> Folder-specific rules. Root `CLAUDE.md` standing rules still apply here.

1. Read `AGILE_GUIDE.md` once. It is the source of truth for the process.
2. Never estimate in hours or story points. Use T-shirt size only.
3. Rank work by value (Impact, Urgency, Dependencies, Risk). See `PRIORITIZATION.md`.
4. A sprint is one week and one GitHub milestone. A PI is a D increment.
5. Write a sprint plan, review, and retro in `sprints/S<nn>/` every sprint.
6. Retro actions become issues with the `retro` label. Owner them.
7. Releases follow `RELEASE_GUIDE.md`. SemVer tags. Update `CHANGELOG.md`.
8. The board is the single view of work. Columns: Backlog, Refined, Sprint Ready, In Progress, Review, Done.
9. Keep In Progress to a max of 2 items. One person cannot review more at once.
