# Retrospective

How to run a retro and track the actions.

## When

After every sprint review. 20 minutes is enough.

## Format

Answer three questions. Keep it honest and short.

1. **What went well?** Keep doing it.
2. **What did not go well?** Name the problem, not the person.
3. **What will we change?** One or two actions, no more.

## Steps

1. Copy `templates/sprint-retro.md` into `sprints/S<nn>/retro.md`.
2. Discuss the three questions.
3. Write one or two **action items**. Each action is small and testable.
4. Create an issue for each action. Add the `retro` label. Owner it.
5. Add the actions to the next sprint if they are small.
6. Review last sprint's actions. Mark then done or dropped.

## Good actions

- Small. Can be done in one sitting.
- Testable. You can tell if it happened.
- Owned. One person is responsible.

## Bad actions

- "Communicate better." Not testable.
- "Fix everything." Too big.

## Rule

If an action is not an issue, it will not happen.
Every retro action becomes an issue with the `retro` label.
