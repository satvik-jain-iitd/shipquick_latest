# Prescriptive ADR for Observability Frameworks

Instrumentation of your application is based on the specific circumstance and use case, as outlined in the below table.

___ELF is the starting point for observability, which should meet the majority of your requirements for logs, tracing and metrics. Where substantiated, you can use Dynatrace and Splunk in addition to ELF, to get the data richness you need for your application. App teams to document with EA Playbook ADRs, the reasons for not using ELF and exclusive need for using options other than ELF.___



> :memo: __Note:__ This document currently provides guidance with a primary focus on application observability.

| Use Case                                                                                                                                                                                                       | Observability                                            | Details & Examples                                                                                                                                                                                                                                                                                                                                                                                    |
|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:---------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| I need logging to aggregate my application logs                                                                                                                                                                | <font color='lightgreen'>**ELF**</font>                  | Logs enable troubleshooting and provide an understanding of your application interactions.                                                                                                                                                                                                                                                                                                            |
| I need __Distributed Tracing__ (OpenTracing / OpenTelemetry)                                                                                                                                                   | <font color='lightgreen'>**ELF** </font>                 | You can enable distributed tracing for your application using ELF by instrumenting traces using OpenTelemetry (OTel) SDKs.                                                                                                                                                                                                                                                                            |
| I am producing OpenTelemetry (OTel) metrics which I need to store, visualize, monitor, and alert                                                                                                               | <font color='lightgreen'>**ELF** </font>                 | Application metrics => Latency, Traffic, Volume, Errors and Saturation Signals.                                                                                                                                                                                                                                                                                                                       |
| I want to use native Prometheus and get metrics for my infrastructure, application or service quality<br/>OR<br/>I already use Prometheus and I want to combine existing metrics with other available metrics. | <font color='lightgreen'>**Prometheus & Grafana**</font> | This solution is still in development for general availability for all GI services.                                                                                                                                                                                                                                                                                                                   |
| I need distributed tracing that includes the Mainframe                                                                                                                                                         | <font color='lightgreen'>**Dynatrace**</font>            | <ul><li>Provides visibility into upstream & downstream transactions and traces flowing into and out of your application and mainframe processes.</li> <li> OTel roadmap for mainframe is in discussion with IBM with potential for pilot in 2024. </li></ul>                                                                                                                                          |
| I need key performance metrics for variable application conditions and user actions                                                                                                                            | <font color='lightgreen'>**Dynatrace**</font>            | <ul><li>Provides various types of metrics: Infra, Service, Process level Metrics, Extensions for additional metrics, Calculated, User Session and User Action (DT One Agent & Custom Metrics & Extensions & RUM).</li> <li> Feed custom metrics into Dynatrace via metric ingest to bring external data into DT for anomaly detection and alerting (for ex. Prometheus metrics). </li></ul>           |
| I need observability for third party or proprietary applications.                                                                                                                                              | <font color='lightgreen'>**Dynatrace**</font>            | COTS generally cannot be instrumented with OpenTelemetry tools.<br /><br /><font color='orange'> NOTE:</font> If the application produces OTel compliant telemetry use ELF.                                                                                                                                                                                                                           |
| I need logging for third party or proprietary applications OR My app is incompatible with OTel                                                                                                                 | <font color='lightgreen'>**Splunk** </font>              | These generally cannot be instrumented with OpenTelemetry tools.<br /><br /><font color='orange'> NOTE:</font> If the application produces OTel compliant logs use ELF.                                                                                                                                                                                                                               |
| I need business level intelligence, business process monitoring, reporting or analytics.                                                                                                                       | <font color='lightgreen'>**Splunk** </font>              | <ul><li>Business level KPIs.</li> <li> I need to know the status of my campaign, what's being consumed, being fulfilled, real-time.</li> <li> Real-time data for managing CCP staffing, validating merchant transaction. </li></ul>                                                                                                                                                                   |
| I need to understand the performance (e.g. APM) of my application stack.                                                                                                                                       | <font color='lightgreen'>**Dynatrace**</font>            | Provides CPU utilization of the processes within method hotspots, threads and memory behavior, down to the code level (application profiling).                                                                                                                                                                                                                                                        |
| I need to see real-time, my Customers UI experience within my Web or Mobile application - Digital Experience Monitoring / Real User Monitoring (RUM)                                                           | <font color='lightgreen'>**Dynatrace**</font>            | <ul><li>Provides metrics of overall web page performance and specifically user session experience.</li> <li> Visibility into front end performance such as response time, throughput, and failures from a user perspective.   </li></ul>                                                                                                                                                              |
| I need Real User Monitoring (RUM, including backend visibility)                                                                                                                                                | <font color='lightgreen'>**Dynatrace**</font>            | <ul><li>Dynatrace RUM & One Agent combine to provide visibility of a transaction that begins at a web URL and the corresponding back-end services are monitored using Dynatrace agent instrumentation.</li> <li> Allows user to understand how frontend performance impacts are correlated to back-end method & code level performance and vice versa using only Dynatrace instrumentation.</li></ul> |
| I need to monitor the availability of my application & API's via Synthetics to understand how it will respond to typical user behavior and transactions before they occur.                                     | <font color='lightgreen'>**Dynatrace** </font>           | <ul><li>An availability monitoring capability done by using a simulation or scripted recording of transactions which are preset to run against a page or API. </li> <li> This can be done within multiple regions - EMEA, LAC, APAC etc., and tested from locations worldwide, at configurable time intervals.  </li></ul>                                                                            |
| I need Session Replay so I can watch a user session in a web application from start to finish.                                                                                                                 | <font color='lightgreen'>**Dynatrace**</font>            | The ability to watch a user's experience from start to finish within a web application, including their inputs and page performance.<br /><br /><font color='orange'> NOTE:</font> Due to HW & SW investment considerations for Session Replay, engagement and discussion with the Dynatrace team is required at this time.                                                                           |
| I need comprehensive full-stack Web UI observability to gain clear visibility into both Server-Side Rendering (SSR) and Client-Side Rendering (CSR) calls..                                                    | <font color='lightgreen'>**UXPulse**</font>              | Provides unified visibility across both server-side rendering (SSR) and client-side rendering (CSR), enabling comprehensive monitoring of the full user journey leading to define custom user-centric metrics such as Visually Complete Time, Speed Index, and Cumulative Layout Shift (CLS).<br /><br /><font color='orange'>                                                                        |
| I need long-term observability data retention to perform year-over-year trend analysis and enable correlation across multiple application and infrastructure data sources for proactive performance and reliability insights...                                                    | <font color='lightgreen'>**Lakemetrics**</font>              | <ul><li><b>Support Longer Data Retention</b>: Maintain extended observability data to enable historical comparisons, compliance needs, and deep retrospective analysis beyond standard retention windows. </li> <li><b> Enable Year-over-Year Trend Analysis</b>: Leverage historical telemetry to identify seasonal patterns, performance regressions, capacity growth trends, and SLA/SLO adherence over time.  </li><li><b>Correlate Multi-Source Telemetry for Proactive Insights</b>: Integrate and analyze application, infrastructure, and dependency data to detect systemic issues early, improve root cause analysis, and drive reliability optimization.</li></ul>                                                                          |
